# 13 — Сборка очереди и runner сессии

**Зависит от:** 09, 11, 12
**Результат:** работающий экран `/session` — «Продолжить обучение» проходится от начала до конца.

---

## Требования: FR-80, FR-81, FR-82, FR-110

## Шаги

### 1. `learning/session/build-learn-queue.ts`

```ts
buildLearnQueue(input: {
  now: number;
  dueSkills: SkillRecord[];
  newWordsBudget: number;          // из настроек, FR-133
  candidateNewWords: WordIndexEntry[];
  targetSize: number;              // обычно 20
}): QueuePlan
```

Приоритет:

```text
1. просроченные повторения (due < now), самые старые первым
2. навыки в состоянии learning/relearning
3. новые слова — до newWordsBudget, по возрастанию rank в пределах активного уровня
```

Правило: **новые слова добавляются последними в приоритете, но перемешиваются по очереди**,
чтобы сессия не была «20 повторений, потом 5 новых» — это утомительно и хуже для запоминания.

Для нового слова создаётся навык `vocab:pl-ru`. Навык `vocab:ru-pl` **не создаётся сразу**:
он появится, когда `pl-ru` дозреет. Это и есть разнесение прогрессии по времени (FR-81) —
без искусственного сценария «первой встречи».

### 2. Zustand-стор сессии

`stores/session.store.ts` — структура в `architecture.md` §10. Хранит только то, что нужно
для отрисовки текущего экрана.

**Важно:** каждый ответ немедленно пишется в Dexie через `applyAnswer` (задача 05).
Прерванная сессия (закрыл вкладку, сел телефон) не теряет прогресс.
Zustand — не буфер для отложенной записи.

### 3. `SessionRunner`

```text
прогресс-бар (i / N)
  ↓
рендер упражнения по типу через реестр компонентов
  ↓
ответ → grade → applyAnswer → feedback
  ↓
Далее → следующее упражнение
  ↓
очередь пуста → /session/result
```

Реестр компонентов — `Record<Exercise['type'], ComponentType>`: новый тип упражнения
подключается одной строкой, runner не меняется.

### 4. Демпфирование при повторе

`firstAnswerBySkill: Map<SkillId, Rating>` — если навык уже отвечен в этой сессии,
`applyAnswer` вызывается с `srsApplied: false` (задача 11, правило 1).

### 5. Восстановление сессии

Активная сессия сохраняется в `sessions` при старте (`startedAt`, `mode`).
При возврате в приложение с незавершённой сессией — предложить продолжить или начать заново.
Очередь пересобирается, уже отвеченные навыки исключаются по `reviewLogs` этой сессии.

### 6. Выход из сессии

Кнопка «Выйти» с подтверждением. Прогресс уже сохранён, терять нечего — но пользователя
надо предупредить, что сессия закроется.

### 7. Настройка размера

`targetSize` и `newWordsBudget` — из настроек (FR-133). Дефолт: 20 заданий, 10 новых слов в день.

## Acceptance

- [ ] «Продолжить обучение» с главной запускает сессию без дополнительных экранов
- [ ] Очередь корректно смешивает повторения и новые слова, а не выдаёт их блоками
- [ ] Просроченные повторения идут раньше новых слов
- [ ] Для нового слова создаётся только `vocab:pl-ru`, не оба направления сразу
- [ ] Ответ записан в Dexie **до** показа обратной связи (проверить: закрыть вкладку сразу после ответа → прогресс есть)
- [ ] Повторный ответ на тот же навык в сессии не меняет `SkillRecord`
- [ ] Незавершённая сессия предлагается к продолжению после перезагрузки
- [ ] Дойти до конца очереди → редирект на экран результатов
- [ ] Сессия проходится полностью с клавиатуры
- [ ] `newWordsBudget = 0` даёт сессию только из повторений; при пустой очереди — осмысленный `EmptyState`

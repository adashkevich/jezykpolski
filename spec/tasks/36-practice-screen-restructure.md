# 36 — Перестройка экрана «Практика»

**Зависит от:** 19, 27, 29, 30, 31, 32, 33
**Результат:** «Выбор перевода», «Написание по-польски» и «Сопоставление» тренируют слова
любой части речи и предлагают повторить сразу после завершения; их кнопка «Начать» видна
без разворачивания; тренировка форм слов — три независимых блока (по одному на
существительные/прилагательные/глаголы) вместо одного общего конфигуратора; побуквенный
ввод — по центру, а раскрытое «Показать слово» слово рисуется обычным текстом; последние
две пары «Сопоставления» не засчитываются в SRS.

---

## Требования: FR-55, FR-136, FR-137, FR-138, FR-139, FR-140, FR-147, FR-148, FR-149, FR-150, FR-151, FR-152

## Зачем

Экран `/practice` (`TrainingSetupScreen.tsx`) с задачи 19 устроен вокруг одной части речи:
табы «Раздел» (NOUN/VERB/ADJ) в блоке «Выборка слов» задают `PracticeConfig.section`, и
**все** блоки — включая три чисто лексических дрилла из задач 27/31 — берут слова из одной
и той же POS-отфильтрованной выборки (`resolvePracticeCandidateWords` всегда ставит
`pos: [config.section]`). Но «Сопоставление», «Выбор перевода» и «Написание по-польски» —
упражнения на перевод, которым часть речи вообще не нужна: они тренируют навыки `vocab:*`,
а не морфологию. Табы наверху делают недостижимым целый класс слов (наречия — `ADV` — не
входят ни в одну вкладку вообще) и заставляют переключать раздел ради дрилла, который к
разделу не имеет отношения.

Отдельно: задача 32 свернула все блоки по умолчанию, включая три лексических пресета, у
которых внутри нет ничего, кроме кнопки «Начать» — раскрытие только стоило лишнего тапа.
После лексического дрилла пользователь либо попадает на главную (`/`, через `/session`),
либо (для «Сопоставления») молча возвращается на `/practice` — предложения повторить нет
нигде, хотя это ровно тот тип упражнения, который логично прогнать несколько раз подряд.

И наконец в «Сопоставлении» (задача 27) последняя пара выбора не требует вовсе, а
предпоследняя — 50%-ная догадка: их правильное сопоставление ничего не говорит о знании
слова, но сегодня засчитывается в `reviewLogs`/SRS наравне с первыми тремя.

## 1. Общая выборка без части речи

**`features/session-runner/lib/session-scope.ts`**

```ts
/** Раздел "Выборка слов" — уровень/статус/частотность, без части речи. */
export interface LexicalWordFilter {
  readonly upToLevel: LevelValue | null
  readonly status: readonly WordStatus[]
  readonly topN: 500 | 1000 | 2000 | 5000 | null
}

/** Аналог `resolvePracticeCandidateWords`, но без `pos`: не грузит парадигмы (лексическим
 *  дриллам нужен только `WordId`), поэтому дешевле на порядок. */
export async function resolveLexicalCandidateWordIds(
  filter: LexicalWordFilter,
): Promise<WordId[]>
```

`{ kind: 'practice-extra' }` получает поле `readonly filter: LexicalWordFilter` — нужно,
чтобы «Ещё» на экране результата и в «Сопоставлении» пересобрали новый батч без обратного
похода на `/practice`. `parseSessionScope` читает его как есть.

**`learning/practice/lexical-batch.ts`** (новый чистый модуль)

- `MATCHING_PAIR_COUNT = 5`, `VOCAB_DRILL_BATCH_SIZE = 10` — переезжают из
  `TrainingSetupScreen.tsx` (были локальными константами задач 27/31).
- `sampleWordBatch(items, n, seed)` — переезжает туда же локальный `seededSample`
  (мулбери32) из `TrainingSetupScreen.tsx` — теперь у него три места вызова (экран,
  «Сопоставление», экран результата), а не одно.
- `MATCHING_UNGRADED_TAIL = 2` и `shouldGradeMatch(matchIndex, totalPairs)` — см. §4.

**`features/training-setup/hooks/useLexicalCandidateWords.ts`** (новый)

Тот же паттерн, что у `usePracticeCandidateWords.ts` (ключ — сериализованный фильтр,
предыдущий результат не пропадает, пока грузится новый): `{ wordIds, loading }`.

## 2. Тренировка форм — три независимых конфигурации

**`features/training-setup/lib/practice-config.ts`**

- `PracticeFormsConfig` — то, что раньше было частью `PracticeConfig`, минус `section` и
  минус выборка (`includeTranslation`/`dimensionSelection`/`exerciseTypes`/`targetSize`).
- `PracticeScreenState = { filter: LexicalWordFilter; formsBySection: Record<PracticeSection,
  PracticeFormsConfig> }` — новое состояние экрана целиком, хранится в `settings` под новым
  ключом `practiceScreenState` (аналог `practiceBlockUsage` из задачи 33 — новой
  Dexie-таблицы/миграции не требует).
- `practiceConfigFor(state, section)` собирает `PracticeConfig` из `filter` +
  `formsBySection[section]` — тот самый тип, который `resolvePracticeCandidateWords` /
  `buildPracticeQueue` / `useSessionBootstrap.ts` продолжают потреблять без изменений.
- Одноразовая миграция: если `practiceScreenState` ещё нет, читается легаси
  `lastPracticeConfig` (задача 19) — из него засеиваются `filter` и
  `formsBySection[legacy.section]`, две другие секции получают дефолт. Легаси-ключ после
  этого больше никогда не пишется.
- `sectionFromFilterPos` сохраняется, но меняет назначение: входящий `/words`-фильтр с
  одной частью речи теперь не выбирает вкладку (вкладок больше нет), а определяет, какой
  из трёх блоков форм открыт при входе на экран.

**`features/training-setup/hooks/usePracticeCandidateWords.ts`**

Параметр становится `PracticeWordFilter | null`. `null` (блок формы свёрнут) — фетч не
запускается вовсе. Экран передаёт не-`null` фильтр только для **открытого** блока форм:
дорогая загрузка парадигм происходит по факту раскрытия, а не на каждом входе на экран.

## 3. `TrainingSetupScreen.tsx`

- Заголовок — статичная «Практика» (не «Тренировка существительных»/… — раздела у экрана
  больше нет).
- «Выборка слов» — без `role="tablist"`: только «Уровень», «Статус», «Частотность» и живой
  счётчик «Найдено N слов» (без «форм» — это переехало внутрь блоков форм).
- Порядок блоков (задача 33) расширяется до 6 id: `vocab-choice`, `vocab-spelling`,
  `matching`, `forms-NOUN`, `forms-ADJ`, `forms-VERB`. Существующая запись `'forms'` в
  `practiceBlockUsage` не входит в новый `defaultOrder` и по уже документированному
  поведению `orderBlocks` тихо игнорируется — три новых блока форм стартуют со счётом 0,
  отдельной миграции карты использования не требуется.
- Три лексических блока — новый компонент `TrainingActionBlock` (без `aria-expanded`,
  всегда открыт, кнопка «Начать» — прямой потомок): `TrainingBlock.tsx` из задачи 32
  остаётся неизменным и обслуживает только три блока форм.
- Три блока форм — `TrainingBlock` c id `forms-NOUN`/`forms-ADJ`/`forms-VERB`, заголовки
  «Формы существительных»/«...прилагательных»/«...глаголов»; тело — ровно то, что раньше
  было единственным конфигуратором («Что тренировать» → измерения раздела → «Тип задания»
  → «Количество заданий» → пустая выборка → «Начать»), плюс возвращённый внутрь счётчик
  «Найдено N слов, M форм» для этой секции. Аккордеон (не более одного блока форм открыт
  одновременно) — тот же паттерн, что и в задаче 32, теперь только среди трёх блоков форм.

## 4. «Ещё» и необсчитываемый хвост «Сопоставления»

**`features/session-runner/components/PracticeDrillActions.tsx`** (новый) — «Ещё» +
«К списку практик», используется и `SessionResultPage`, и `MatchingPracticePage`.

**Сопоставление не засчитывает последние `MATCHING_UNGRADED_TAIL` (2) пары**: с двумя
оставшимися парами правильный выбор — либо 50%-ная догадка (предпоследняя пара, один из
двух оставшихся вариантов), либо вообще не выбор (последняя пара — единственный оставшийся
вариант на обеих сторонах). Визуально ничего не меняется (зелёная подсветка, галочка,
«Сопоставлено N из M» — как обычно), но `useMatchingPracticeSession.ts#gradePair` пропускает
`submitAnswer`/`ensureSkill` для этих пар, опираясь на чистый `shouldGradeMatch` из
`lexical-batch.ts`. Батч из ≤ `MATCHING_UNGRADED_TAIL` пар не засчитывает ничего вовсе —
вырожденный случай, а не ошибка.

`MatchingPracticePage.tsx` перестаёт уходить с `/practice/matching` по «Готово» — вместо
этого показывает `PracticeDrillActions`; «Ещё» пересобирает батч через
`resolveLexicalCandidateWordIds(filter)` + `sampleWordBatch` и делает
`navigate(..., { replace: true })` с новым `wordIds`.

`SessionPage.tsx#goToResults` для scope `practice-extra` прокидывает `{ variant, filter }`
в стейт `/session/result`; `SessionResultPage.tsx` при наличии `practiceExtra` показывает
`PracticeDrillActions` вместо «Закончить» (при наличии ошибок «Разобрать ошибки» остаётся
отдельной строкой сверху). Тренировка форм слов такой кнопки не получает — она по-прежнему
заканчивается «Разобрать ошибки»/«Закончить», это разовая настроенная сессия, а не дрилл
«прогони ещё раз».

## 5. Побуквенный ввод (`LetterSlotsInput.tsx`)

Два точечных изменения (оба — прямой запрос пользователя, отступление от задач 29/30):

1. Ряд слотов центрируется (`justify-center` вместо `justify-start`) — контейнер остаётся
   `overflow-x-auto`, длинное слово по-прежнему скроллится внутри себя на 320px.
2. `CELL_CLASS.revealed` теряет курсив и приглушённый цвет — раскрытое «Показать слово»
   слово рисуется тем же цветом текста, что обычный ответ, тем же (моноширинным) шрифтом
   ряда. Пунктирное подчёркивание остаётся — это единственный оставшийся неcветовой признак,
   которого требует NFR-11.

## Границы

- `PracticeSection` остаётся `NOUN | VERB | ADJ` — блока «Формы наречий» нет (у ADV только
  два навыка `adv:degree:*`, недостаточно для отдельного блока, как и решила задача 19).
- `build-practice-queue.ts`, `useSessionBootstrap.ts`, `picker.ts`, `generate.ts`,
  `MatchingExercise.tsx`, `TrainingBlock.tsx`, SRS-политика не меняются.
- Ранжирование блоков (задача 33) не переписывается — расширяется только список id.
- Тренировка форм слов не получает кнопку «Ещё» — см. §4.

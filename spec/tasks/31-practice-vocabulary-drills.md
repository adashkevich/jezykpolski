# 31 — Пересборка набора Practice-упражнений: лексические дриллы вместо викторин

**Зависит от:** 19, 27, 28, 29
**Результат:** из Practice убраны «Найди лишний перевод» и «Быстрая классификация части
речи»; вместо них появляются два лексических дрилла батчем — «Выбор перевода PL → RU»
(выбор из 4) и «Написание по-польски RU → PL» (побуквенный ввод), оба уважают текущую
выборку слов на экране тренировки.

---

## Требования: FR-50, FR-53, FR-137, FR-138 (FR-56 и FR-57 отменяются)

## Зачем

Задача 27 добавила в Practice два типа заданий, которые не тренируют ничего из того, ради
чего приложение существует: «лишний перевод» проверяет умение заметить чужеродное слово в
списке, «часть речи» — грамматическую категорию, которая в интерфейсе и так подписана у
каждого слова. Ни то, ни другое не создаёт и не укрепляет навык `vocab:*`: оба работают
через искусственно материализованный `vocab:pl-ru` только чтобы было к чему привязать
`reviewLogs`.

Одновременно ровно те два упражнения, которые реально составляют два этапа изучения слова
(задача 28, FR-80: этап 1 — выбор значения PL→RU, этап 2 — написание по-польски RU→PL),
в Practice **недоступны точечно**: сейчас туда можно попасть только через ежедневную
Learn-очередь, когда FSRS сам решит, что пора. Пользователь, который хочет «прогнать 15 слов
на перевод прямо сейчас», такой возможности не имеет — чекбокс «Перевод» в конфигураторе
подмешивает перевод к формам слов, а не даёт отдельную тренировку.

Эта задача меняет ровно набор Practice-точек входа: убирает две бесполезные и ставит на их
место два дрилла, повторяющие оба этапа изучения слова.

## 2. `PracticeExtraVariant` — два новых значения

`features/session-runner/lib/session-scope.ts`:

```ts
export type PracticeExtraVariant = 'vocab-choice' | 'vocab-spelling'
```

Скоуп `{ kind: 'practice-extra'; variant; wordIds }` и его разбор в `parseSessionScope`
остаются как есть — меняется только множество вариантов и то, какой навык за ними стоит:

| Вариант | Навык | Упражнение | Направление |
|---|---|---|---|
| `vocab-choice` | `vocab:pl-ru` | `choice` (4 варианта) | PL → RU |
| `vocab-spelling` | `vocab:ru-pl` | `input` (побуквенный ряд слотов) | RU → PL |

Заголовок модуля переписывается под новую пару (сейчас он объясняет, почему «лишний
перевод»/«часть речи» идут через обычную очередь) — то же обоснование остаётся верным:
оба дрилла односложные и автопроверяемые, поэтому проходят штатным путём
`SessionRunner`/registry, просто с форсированным типом вместо `pickExerciseType`.

## 3. Материализация навыка и источник слов

`features/session-runner/hooks/useSessionBootstrap.ts`, ветка `scope.kind === 'practice-extra'`:

1. Дименсия навыка выбирается по варианту — `'vocab:pl-ru'` для `vocab-choice`,
   `'vocab:ru-pl'` для `vocab-spelling`, — вместо нынешнего жёсткого `vocab:pl-ru`. Это же
   значение используется в `excludeSkillIds`-фильтре (иначе «Повторить ошибки» после
   дрилла на написание отсеивал бы не те слова).
2. `materializeQueueItem`'s `'new'`-ветка сейчас создаёт слову только `vocab:pl-ru`; для
   `vocab-spelling` нужен `ensureSkill(wordId, 'vocab:ru-pl')`. Задача 28 уже сделала оба
   этапа штатными для Learn — здесь используется тот же путь, без новой логики
   материализации.
3. `mode: 'practice'` для этого скоупа сохраняется — демпфирование SRS
   (`policy.ts#capRatingForMode`, FR-112) обязано действовать, дрилл не должен разгонять
   расписание сильнее ежедневной сессии.

`features/session-runner/lib/build-session-exercises.ts#generateExtraForWord` вместо двух
удалённых билдеров вызывает уже существующий `generateExercise` с явным типом
(`'choice'` / `'input'`) и направлением из таблицы выше — тем же вызовом, которым идёт
обычный Learn, просто в обход `pickExerciseType`. Никаких новых генераторов эта задача не
добавляет.

**Источник слов** — `candidateWords`, которые экран тренировки уже разрешил через
`usePracticeCandidateWords` для текущих фильтров (тот самый набор, из которого «Сопоставление»
берёт свои пары), а не отдельный сэмплер по частотному индексу. Так оба дрилла подчиняются
уровню/статусу/частотности, которые пользователь видит на экране, и `practice-extra-words.ts`
становится не нужен. Выборка — тот же локальный seeded-сэмпл, что уже используется для
«Сопоставления» (`mulberry32` + `seededSample` в `TrainingSetupScreen.tsx`), с `Date.now()`
в качестве seed, чтобы повторные запуски давали разные батчи.

Размер батча — одна константа на оба дрилла (`VOCAB_DRILL_BATCH_SIZE`, 10). Если в выборке
слов меньше, батч берёт сколько есть; при нулевой выборке кнопка «Начать» блока
дизейблится с тем же пояснением, что уже показывает блок «Сопоставление».

## 4. Блоки на экране тренировки

Два новых блока в `TrainingSetupScreen.tsx` — по форме такие же, как существующий
«Сопоставление» (заголовок, пояснение, своя кнопка «Начать»); конкретное размещение и
сворачивание задаёт задача 32, эта задача только даёт им содержимое:

- **«Выбор перевода (PL → RU)»** — «{N} слов из текущей выборки: выберите правильный перевод
  из четырёх вариантов».
- **«Написание по-польски (RU → PL)»** — «{N} слов из текущей выборки: наберите польское
  слово по буквам».

Оба используют побуквенный ввод и подсветку в точности как в ежедневной сессии — своих
компонентов упражнений эта задача не создаёт, `exercise-registry.tsx` уже умеет
`choice`/`input`.

## 5. Границы

- Чекбокс «Перевод» в конфигураторе форм слов (`config.includeTranslation`) не трогается:
  он про то, подмешивать ли перевод в тренировку **форм**, и остаётся как есть.
- Learn-очередь, `picker.ts` и прогрессия из задачи 28 не меняются вообще.
- Экран статистики не получает новых категорий: оба дрилла пишут `reviewLogs` по обычным
  навыкам `vocab:*` и попадают в существующие срезы сами собой.

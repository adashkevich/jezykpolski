# 35 — Новые слова вводятся по уровням: A1, затем A2 и дальше

**Зависит от:** 07, 11, 13, 23, 24
**Результат:** ежедневная сессия берёт новые слова не «по частотности из всего словаря», а
по уровням сложности: сначала только A1; когда запас невыученных A1 подходит к концу,
к пулу подмешивается A2, затем B1 и так далее до C2.

---

## Требования: FR-110, FR-133, FR-143, FR-144, FR-145, FR-146

## Зачем

`build-learn-queue.ts` сортирует кандидатов ровно одной строкой —
`[...candidateNewWords].sort((a, b) => a.rank - b.rank)`, а `session-scope.ts#resolveGlobalScope`
отдаёт ему `queryWords({ sort: 'frequency', status: ['new'] }, progress)`, то есть **весь
словарь без ограничения по уровню**. Частотность и сложность коррелируют, но далеко не
совпадают: в первой тысяче по рангу спокойно живут служебные и абстрактные слова уровня
B2–C1, и новичок получает их вперемешку с `kot`/`dom` уже в первую неделю. Уровень слова
(`WordIndexEntry.level`, `LEVEL_VALUES` = A1…C2) при отборе новых слов сейчас не участвует
вообще — он используется только как фильтр списка `/words` и как разрез статистики.

Нужен нормальный порядок прохождения: пока не разобран A1, C1 в ежедневной сессии
появляться не должен.

---

## 1. `learning/session/level-gate.ts` — новый чистый модуль

Без React и Dexie (`learning/**` — чистый слой). Решает две вещи: какие уровни **открыты**
и в каком порядке брать из них слова.

```ts
/** Сколько невыученных слов уровня должно остаться, чтобы открылся следующий.
 *  Порог, а не ноль: последние слова уровня — самые редкие и самые «залипающие»
 *  (пользователь мог отложить их свайпом), ждать их полного исчерпания значило бы
 *  застревать на A1 месяцами. */
export const LEVEL_UNLOCK_REMAINING = 50

export interface LevelPoolCounts {
  /** Сколько слов уровня ещё имеет статус `new` (ни одного навыка не заведено). */
  readonly unstartedByLevel: Readonly<Record<LevelValue, number>>
  /** Есть ли на уровне хотя бы одно начатое слово. */
  readonly startedByLevel: Readonly<Record<LevelValue, boolean>>
}

/** Уровни, из которых сейчас разрешено брать новые слова, в порядке LEVEL_VALUES.
 *  Всегда непустой, пока в словаре вообще остались неначатые слова. */
export function unlockedLevels(counts: LevelPoolCounts, startLevel: LevelValue): LevelValue[]

/** Порядок кандидатов внутри сессии: смешивает два младших непустых открытых уровня
 *  в пропорции 2:1, внутри уровня — по возрастанию `rank`. */
export function orderNewWordCandidates(
  candidates: readonly WordIndexEntry[],
  unlocked: readonly LevelValue[],
): WordIndexEntry[]
```

### Правила открытия уровня (`unlockedLevels`)

1. Уровни ниже `startLevel` (см. §3) закрыты всегда — их слова в ежедневную сессию не
   попадают.
2. `startLevel` открыт всегда.
3. Уровень `L+1` открыт, если открыт `L` **и** выполнено хотя бы одно из:
   - `unstartedByLevel[L] <= LEVEL_UNLOCK_REMAINING` — уровень подходит к концу;
   - `startedByLevel[L+1] === true` — на уровне уже есть начатые слова.
     Это правило-храповик: однажды открытый уровень не закрывается обратно, когда
     пользователь начал в нём слова, а счётчики младшего уровня подросли (импорт бэкапа,
     сброс прогресса части слов). Без него сессия могла бы «забыть» уже изучаемые слова.
4. Открытие каскадное: если A1 пуст, а A2 весь начат, откроются и A3-эквивалент (B1), и
   дальше — по тем же правилам, за один проход по `LEVEL_VALUES`.

### Правила смешивания (`orderNewWordCandidates`)

Открыть A2 «в пул» и при этом отсортировать пул по `(уровень, rank)` означало бы, что A2
не увидят, пока не кончатся все 50 оставшихся A1 — то есть ещё неделю. Поэтому смешивание
явное:

- `L0` — младший открытый уровень, в котором ещё есть кандидаты; `L1` — следующий за ним
  такой же.
- Слоты новых слов раздаются по циклу `L0, L0, L1` — две трети младшему уровню, треть
  следующему. Когда `L1` пуст, всё уходит `L0`; когда пуст `L0`, роли сдвигаются вверх.
- Внутри уровня — строго по возрастанию `rank` (частотные первыми), как и было.
- Функция чистая и детерминированная: ни `Math.random()`, ни чтения часов —
  `buildLearnQueue` уже держит это свойство и не должен его потерять.

Тесты (`level-gate.test.ts`):

- при полном A1 открыт только A1; C1-слово в кандидаты не попадает ни при каком `rank`;
- при `unstarted A1 = 50` открывается A2, при 51 — ещё нет;
- начатое слово A2 держит A2 открытым, даже если A1 снова полон;
- `orderNewWordCandidates` при двух непустых уровнях даёт паттерн 2:1 и сортировку по
  `rank` внутри уровня;
- пустой `L1` не ломает цикл — все слоты уходят `L0`;
- `startLevel = 'B1'` полностью исключает A1/A2 из выдачи.

## 2. Подключение к отбору кандидатов

`features/session-runner/lib/session-scope.ts#resolveGlobalScope` — единственное место, где
включается воротник:

1. Считает `LevelPoolCounts` из уже загруженных `getAllWordProgress()` и индекса
   (`getIndexStore().byLevel` — проход по 7998 записям, никаких новых запросов к БД).
2. Вызывает `unlockedLevels(counts, startLevel)` и сужает `queryWords({ sort: 'frequency',
   status: ['new'] }, progress)` до открытых уровней (`levels: unlocked` в `WordQuery` —
   поле уже существует).
3. `buildLearnQueue` получает кандидатов, уже упорядоченных `orderNewWordCandidates`, и его
   собственную сортировку по `rank` для новых слов нужно **убрать** — иначе она немедленно
   разрушит перемешивание уровней. `BuildLearnQueueInput.candidateNewWords` документируется
   как «уже упорядоченный вызывающей стороной список» (там же, где уже сказано, что
   вызывающая сторона решает, какие слова вообще подходят). Существующие тесты
   `build-learn-queue.test.ts`, которые полагались на внутреннюю сортировку, передают
   отсортированный вход явно.

**Где воротник не действует** (сознательно):

- `resolveFilterScope` — сессия, запущенная из отфильтрованного `/words` (в том числе с
  явно выбранным уровнем): пользователь уже сказал, что хочет; перекрывать его выбор
  скрытым правилом нельзя.
- `resolveWordScope` / `resolveSkillScope` / режим «Ошибки» — там новых слов либо нет, либо
  слово названо поимённо.
- Practice целиком (`build-practice-queue.ts`) — там есть собственный фильтр «Уровень».

## 3. Настройка стартового уровня

Ключ `newWordsStartLevel` в `settings` (значения `LEVEL_VALUES`, по умолчанию `'A1'`) —
через существующий `settings.repository.ts`, новой Dexie-версии не требуется. В
`features/settings/components/LearningSettingsSection.tsx` появляется селект «Начинать с
уровня» с пояснением: «Новые слова в ежедневной сессии берутся с этого уровня и выше.
Уровни ниже не предлагаются». Это нужный клапан для тех, кто пришёл не с нуля, — иначе
человеку с B1 придётся пролистать 2000 слов A1, чтобы дойти до своих.

Смена настройки на более высокий уровень не трогает уже начатые слова: они остаются в
повторениях (воротник управляет только вводом **новых**).

## 4. Видимость для пользователя

Скрытое правило, меняющее содержимое ежедневной сессии, обязано быть видимым, иначе оно
читается как баг «почему больше не появляются новые слова»:

- **Главный экран** — строка под кнопкой «Продолжить обучение»: «Сейчас изучаем: A1 ·
  осталось N слов» (`N` — `unstartedByLevel` текущего младшего открытого уровня). Когда
  открыто два уровня — «A1 + A2».
- **Экран статистики** — в существующем разрезе «По уровням» (`stats.repository.ts`
  уже отдаёт бакеты по `LEVEL_VALUES`) открытые уровни помечаются, закрытые показываются
  приглушённо с подписью «откроется позже». Новых запросов и новых бакетов не заводится.

---

## 5. Граничные случаи

- Словарь кончился (все слова начаты) — `unlockedLevels` возвращает все уровни,
  `candidateNewWords` пуст, сессия состоит из одних повторений; главный экран показывает
  существующее «нет новых слов» состояние, без нового пустого экрана.
- Уровень целиком меньше порога (в корпусе такой уровень возможен) — правило 3
  срабатывает сразу, и он не становится тупиком.
- Свайп «Знаю» из задачи 16 переводит слово из `new`, то есть уменьшает
  `unstartedByLevel` — это ровно то поведение, которое нужно: массовое «это я знаю» по A1
  честно приближает открытие A2.

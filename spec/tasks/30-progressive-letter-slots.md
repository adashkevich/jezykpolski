# 30 — Растущий ряд слотов: длина слова скрыта до конца набора

**Зависит от:** 28, 29
**Результат:** в упражнениях с набором ответа (`input` — этап 2 «напиши по-польски»,
`form-input` — форма слова) ряд слотов больше не показывает длину слова заранее: виден
ровно один активный пустой слот, и новый появляется только после того, как предыдущая
буква введена и слово ещё не закончилось.

---

## Требования: FR-53, FR-59 (переформулируется), FR-136, FR-84, FR-85, FR-86

## Зачем

Задача 29 сделала ряд слотов по одной ячейке на каждую букву эталона сразу при рендере
(`letter-attempt.ts#createLetterAttempt` → `buildCells(canonical)`, `LetterSlotsInput.tsx`
рисует весь `attempt.cells`). Это дало письменную опору, но заодно бесплатно выдало длину
слова — самую сильную подсказку из всех: `sześć` от `siedem` отличаются в первую очередь
длиной, и при видимом ряду из 5 клеток вспоминать уже нечего. Побочно длина протекает и
через вёрстку: ширина ячейки в `LetterSlotsInput` вычисляется от количества букв, так что
даже беглый взгляд на ряд до первого нажатия сообщает, длинное слово или короткое.

Цель — вернуть упражнению характер воспроизведения: пользователь начинает набирать
вслепую и узнаёт, что слово кончилось, ровно в тот момент, когда упражнение
автозавершается на последней верной букве (поведение FR-84 из задачи 29 не меняется).

---

## 1. `learning/exercises/letter-attempt.ts` — прогрессивное раскрытие ячеек

Модуль остаётся чистым (без React/Dexie) и сохраняет весь свой публичный контракт
(`createLetterAttempt`/`typeLetter`/`typeLetters`/`eraseLetter`/`revealCurrentLetter`/
`revealAll`/`attemptValue`/`submittedAnswer`/`outcomeOf`). Меняется только то, какие ячейки
считаются **видимыми**.

`LetterAttempt` получает одно новое производное поле:

```ts
export interface LetterAttempt {
  // ...всё как в задаче 29
  /** Сколько первых ячеек `cells` разрешено показывать. Всегда:
   *  «все заполненные» + разделители за ними + одна активная пустая (если слово не
   *  закончилось). Никогда не больше `cells.length`. */
  readonly visibleCount: number
}
```

Правила:

1. `createLetterAttempt` строит `cells` по эталону ровно как раньше (вся проверка букв,
   отсев кандидатов и автозавершение работают по полному ряду — прогрессивность
   исключительно про отрисовку), но выставляет `visibleCount` в позицию после первой
   буквенной ячейки, включая ведущие разделители, если они есть.
2. После каждого перехода (`typeLetter`, `revealCurrentLetter`, `eraseLetter`)
   `visibleCount` пересчитывается одной чистой функцией `computeVisibleCount(cells, cursor)`:
   курсор плюс все идущие подряд разделители перед ним, плюс сам активный слот. То есть
   разделитель (пробел, дефис, апостроф) всплывает **вместе** со слотом следующей за ним
   буквы, а не заранее: `będziemy robić` показывает пробел только когда набрано `będziemy`.
3. `visibleCount` монотонно не убывает при вводе, но **уменьшается** при `eraseLetter` —
   стёртая буква возвращает ряд к предыдущей длине, иначе бэкспейс становился бы способом
   бесплатно посчитать буквы.
4. `revealAll` (кнопка «Показать слово», FR-85) выставляет `visibleCount = cells.length` —
   раскрытие показывает слово целиком, это его смысл.
5. `revealCurrentLetter` (кнопка «Подсказка», FR-86) двигает `visibleCount` ровно на один
   слот вперёд, как обычное верное нажатие. Подсказка не должна раскрывать длину.
6. `outcomeOf().letterCount` остаётся полным количеством буквенных ячеек — это вход
   `policy.ts` для правила «подсказками открыто всё слово» (задача 29 §2), а не UI-величина.

Тесты (`letter-attempt.test.ts`, дополнение к существующим):

- новая попытка показывает ровно один слот, независимо от длины эталона;
- после каждой верной буквы `visibleCount` растёт на 1 (или на 1 + разделители);
- на неверной букве `visibleCount` не растёт — активный слот остаётся тем же;
- `eraseLetter` возвращает `visibleCount` к предыдущему значению;
- на последней верной букве `complete === true` и `visibleCount === cells.length`;
- `revealAll` открывает весь ряд.

## 2. `features/session-runner/components/LetterSlotsInput.tsx` — рендер и вёрстка

1. Рендерится `attempt.cells.slice(0, attempt.visibleCount)`, а не весь массив.
2. **Ширина ячейки больше не зависит от длины слова.** Сейчас она вычисляется от
   `cells.length` ради умещения самых длинных форм в 320px; это прямая утечка длины.
   Новое правило: фиксированная ширина ячейки (одна константа, тач-таргет ≥ 44px по высоте,
   критерий MVP №14), ряд переносится по `flex-wrap` и, при переполнении, горизонтально
   скроллится внутри своего контейнера — страница на 320px по-прежнему не скроллится вбок.
3. Появление нового слота — без анимации сдвига всего ряда (`prefers-reduced-motion`
   уважается автоматически, если анимации нет вовсе); ряд выравнивается по левому краю,
   чтобы уже набранные буквы не «прыгали» при добавлении слота.

   **Изменено задачей 36** (`36-practice-screen-restructure.md` §5, FR-151): по прямому
   запросу пользователя ряд теперь центрируется (`justify-center`), а не выравнивается по
   левому краю — контейнер остаётся `overflow-x-auto`, так что длинное слово по-прежнему
   скроллится внутри себя на 320px, а не растягивает страницу.
4. `aria-label` скрытого `<input>` не должен называть количество букв. Живой регион с
   текстом вида «Буква N: верно/неверно» остаётся, номер буквы — это позиция уже набранного,
   а не длина слова.
5. Кнопки «Подсказка» и «Показать слово», ряд быстрых польских диакритик, захват ввода
   настоящим `<input>` (см. заголовок компонента) — без изменений.

Тесты (`LetterSlotsInput.test.tsx`, дополнение):

- при монтировании в DOM ровно один пустой слот, сколько бы букв ни было в ответе;
- ввод верной буквы добавляет ровно один слот;
- ввод неверной буквы не добавляет слот;
- «Показать слово» показывает все буквы.

## 3. Что не меняется

## 4. E2E — `e2e/support/exercise.ts`

Хелпер набора ответа не должен опираться на количество отрисованных слотов при старте
задания (сейчас он вправе это делать). Набор идёт посимвольно в скрытый `<input>` до
автозавершения; хелпер «раскрыть слово» использует кнопку, а не подсчёт ячеек.

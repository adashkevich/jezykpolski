# 39 — Экран «Практика» берёт слова из текущего уровня; «Сопоставление» засчитывает оба навыка перевода

**Зависит от:** 35, 36, 37, 38
**Результат:** блока «Выборка слов» на `/practice` больше нет — все шесть тренировок (три
лексических дрилла и три блока форм) сэмплируют слова из того же воротника уровней, что и
новые слова ежедневной сессии; статус и частотность как фильтры убраны без замены. Отдельно:
«Сопоставление» теперь засчитывает оба направления перевода — `vocab:pl-ru` и
`vocab:ru-pl-choice`, — а не только `vocab:pl-ru`.

---

## Требования: FR-55, FR-114, FR-137, FR-138, FR-139, FR-147, FR-150, FR-152, FR-153 (все изменены)

## Зачем

Задача 38 сделала прогрессию уровней в ежедневной сессии строгой: новые слова всегда идут
ровно с одного уровня, следующий открывается только когда предыдущий пройден полностью. Экран
`/practice` этого правила не знал вообще — блок «Выборка слов»
(`TrainingSetupScreen.tsx`) давал выбрать «Уровень» вручную (по умолчанию «Все уровни»),
«Статус» и «Частотность», и все шесть тренировочных блоков сэмплировали слова из этого
фильтра. Свежий пользователь на `/practice` получал слова C2 наравне с A1 — ровно то, против
чего задачи 35/38 строили воротник для ежедневной сессии.

Прямое решение пользователя: пользователь не должен выбирать уровень на `/practice` — выборка
собирается автоматически из слов текущего уровня и ниже (`upToLevel = practicePoolLevel`, тот
же воротник, что у ежедневной сессии), а «Статус»/«Частотность» убираются без замены —
невидимый, нерегулируемый фильтр читался бы как баг.

Отдельно, тоже прямое решение пользователя: «Сопоставление» (задача 27, расширено задачей 36)
засчитывает только один навык из трёх — `vocab:pl-ru` (PL→RU) — хотя сетка одинаково проверяет
оба направления: правильный тап по русской плитке для польского слова и по польской плитке для
русского слова требуют одного и того же знания. Зачёт только одного направления недооценивал
упражнение и не давал ему вести слово через этап 2 (`vocab:ru-pl-choice`, узнавание по-польски)
своим собственным путём.

## 1. Уровень как единая производная величина

**`learning/session/level-gate.ts`** — новая функция `practicePoolLevel(counts, startLevel)`:
уровень, до которого включительно берёт слова `/practice` — `currentNewWordLevel`, если во
всём открытом диапазоне ещё есть неначатые слова, иначе самый старший открытый уровень
(`unlockedLevels` никогда не пуст). В отличие от `currentNewWordLevel` всегда определён — у
экрана практики нет состояния «слов нет вообще».

**`hooks/useLevelGate.ts`** — `LevelGateState` получает поле `practiceLevel: LevelValue`,
вычисленное тем же `practicePoolLevel` поверх уже читаемых `startLevel`/`counts`. Новых
Dexie-запросов не требует.

## 2. Пул лексических дриллов

**`features/session-runner/lib/session-scope.ts`**

- `interface LexicalWordFilter` удалён, вместе с полем `filter` у варианта
  `{ kind: 'practice-extra' }` и его чтением в `parseSessionScope`.
- `resolveLexicalCandidateWordIds()` теперь без параметров: сам читает `startLevel` из
  настроек, `progress` через `getAllWordProgress()`, выводит `upToLevel =
  practicePoolLevel(computeLevelPoolCounts(progress), startLevel)` и вызывает `queryWords({
  upToLevel, sort: 'frequency' }, progress)`. Ни `status`, ни `topN` в запрос больше не
  попадают.
- Это не полный аналог воротника ежедневной сессии: `resolveGlobalScope` дополнительно
  исключает уровни **ниже** `startLevel` целиком (`levels: unlockedLevels(...)`, явный набор).
  `/practice` так никогда не делал — уровень ниже выбранного вручную и раньше не исключался,
  только не превышался (`WordQuery.upToLevel` — потолок по рангу, не диапазон). Задача 39
  переиспользует `practicePoolLevel` только для потолка, не для пола.
- `features/training-setup/hooks/useLexicalCandidateWords.ts` — без параметра; одноразовый
  фетч на маунте вместо кэша по ключу фильтра (внутри одного визита меняться нечему).

## 3. Состояние экрана: только настройки форм

**`features/training-setup/lib/practice-config.ts`** — `PracticeScreenState` теряет поле
`filter`, остаётся `{ formsBySection }`. `DEFAULT_LEXICAL_FILTER` и `applyIncomingFilter`
удалены. `practiceConfigFor(state, section, upToLevel)` берёт `upToLevel` третьим аргументом
(от воротника, не от состояния экрана); в собираемый `PracticeConfig` идёт `status: []`,
`topN: null` — та же семантика «фильтра нет», которую `resolvePracticeCandidateWords` уже
понимает (`config.status.length > 0 ? config.status : undefined`), так что сам тип
`PracticeConfig` и код ниже по стеку не меняются. Старая сохранённая строка настроек с лишним
`filter` читается как есть — поле просто не используется, следующее «Начать» перезапишет
состояние уже без него.

## 4. `TrainingSetupScreen.tsx`

Блок «Выборка слов» убран целиком. `useLevelGate().practiceLevel` — источник уровня для всех
шести блоков; пока он не определён (загрузка), блоки форм не фетчят кандидатов, кнопки «Начать»
неактивны. Заголовок экрана показывает текущий уровень одной строкой («Слова текущего уровня:
A1 и ниже»). Тексты сообщений о пустом пуле переписаны без упоминания фильтров — ослаблять
больше нечего.

## 5. Пересборка батча («Ещё») и вход с `/words`

`MatchingPracticePage.tsx` и `SessionResultPage.tsx` вызывают
`resolveLexicalCandidateWordIds()` без аргумента; `filter` не кладётся в router state ни при
запуске, ни при «Ещё». Входящий `/words`-фильтр (`LearnFab.tsx` → `PracticeSetupPage.tsx`)
больше не влияет на выборку — его единственная роль осталась прежней с задачи 36: выбор,
какой блок форм открыт при входе (`sectionFromFilterPos`).

## 6. «Сопоставление» засчитывает оба направления

**`features/session-runner/hooks/useMatchingPracticeSession.ts#gradePair`** — после проверки
необсчитываемого хвоста (`shouldGradeMatch`, не меняется) градит два навыка вместо одного,
строго последовательно, `vocab:pl-ru` первым:

| Навык | `direction` | `prompt` | `correct`/`answerGiven` |
| --- | --- | --- | --- |
| `vocab:pl-ru` | `'pl-ru'` | `pair.pl` | `pair.ru` |
| `vocab:ru-pl-choice` | `'ru-pl'` | `pair.ru` | `pair.pl` |

Для каждой строки — тот же путь, что и раньше для одной: `ensureSkill` → синтетическое
одноопционное `{ type: 'choice', ... }` → `submitAnswer`. `elapsedMs` считается один раз и
передаётся обоим — это одно взаимодействие пользователя, не два.

Строго последовательно (не `Promise.all`) не ради стиля: оценка `vocab:pl-ru` сама может
завести `vocab:ru-pl-choice` через `answer-pipeline.ts#maybeUnlockNextStage`, когда её
стабильность переваливает за 7 дней (FR-153). Параллельные `ensureSkill`/`submitAnswer` по
одной и той же будущей записи — гонка двух писателей. `ensureSkill` идемпотентен: если записи
ещё нет (обычный случай для слова, только что встреченного в сопоставлении), она заводится
`state: 'new'` и тут же получает первую оценку — «заводить сразу», без ожидания порога FR-153.

`vocab:ru-pl-input` (этап 3, написание) не тронут — сетка никогда не просит набрать слово по
буквам.

## Границы

- SRS-политика (`learning/srs/policy.ts`), `build-practice-queue.ts`, `picker.ts`,
  `resolvePracticeCandidateWords`, воротник ежедневной сессии (`resolveGlobalScope`,
  `unlockedLevels`, `orderNewWordCandidates`) не меняются.
- `features/stats/components/ConfusionCard.tsx` — свой независимый локальный
  `practiceConfigFor` (запуск разбора конкретной пары слов), не трогается.
- `MatchingExercise.tsx`, необсчитываемый хвост (`MATCHING_UNGRADED_TAIL`,
  `shouldGradeMatch`), правило «неверная пара не логируется» — не меняются.
- `vocab:ru-pl-input` не заводится сопоставлением ни при каких условиях.
- Настройка «Начинать с уровня» (`newWordsStartLevel`) по-прежнему не действует на `/practice`
  как пол диапазона — только как часть вычисления потолка через `practicePoolLevel` (см. §2).

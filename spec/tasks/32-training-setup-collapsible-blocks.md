# 32 — Экран тренировки: сворачиваемые блоки и «Начать» внутри своего блока

**Зависит от:** 19, 31
**Результат:** «Настройка тренировки» перестаёт быть одной длинной портянкой: каждая
тренировка — отдельный сворачиваемый блок со своим описанием и своей кнопкой «Начать»
внутри; конфигуратор форм слов становится таким же блоком, уезжает вниз и по умолчанию
свёрнут — его разворачивают кнопкой-заголовком.

---

## Требования: FR-111, FR-113, FR-114, FR-139, FR-140

## Зачем

Сейчас `TrainingSetupScreen.tsx` рендерит подряд: табы раздела → фильтры выборки → «Что
тренировать» → группы измерений (у ADJ их четыре: числа, роды, падежи, степени) → «Тип
задания» → «Количество заданий» → блоки отдельных тренировок со своими «Начать» → и только в
самом конце главную кнопку «Начать», которая запускает **конфигуратор форм**.

Из этого следуют две настоящие проблемы:

1. **Кнопка оторвана от того, что запускает.** Между последним полем конфигуратора и его
   «Начать» стоят три чужих блока, каждый со своей кнопкой «Начать». Четыре одинаково
   подписанные кнопки на экране, и та, что относится к длинной форме сверху, — самая
   дальняя от неё. Пользователь читает это как «кнопка внизу страницы», а не «кнопка этой
   формы».
2. **Всё раскрыто всегда.** Экран открывается на форме из ~30 контролов, даже когда
   пользователь пришёл нажать один дрилл. Тренировка форм — самая громоздкая, но далеко не
   самая частая точка входа.

---

## 1. Модель экрана: пресеты сверху, конфигуратор снизу

Экран становится списком **блоков тренировки**. Блок — это disclosure: строка-заголовок
(кнопка) + разворачиваемое тело; внутри тела — описание, специфичные для блока контролы
(если есть) и **ровно одна кнопка «Начать», которая запускает именно этот блок**.

Порядок сверху вниз:

1. **«Выборка слов»** — не блок тренировки, а общий фильтр: табы раздела (NOUN/VERB/ADJ),
   уровень, статус, частотность, плюс живой счётчик «Найдено N слов, M форм». Остаётся
   всегда развёрнутым и всегда наверху: от него зависят все блоки ниже, и прятать его
   означало бы запускать дриллы вслепую.
2. **Блоки-пресеты** — «Выбор перевода (PL → RU)», «Написание по-польски (RU → PL)»
   (задача 31), «Сопоставление» (задача 27). Своих настроек не имеют, только описание и
   «Начать»; свёрнуты по умолчанию.
3. **«Тренировка форм слов»** — последний блок, свёрнут по умолчанию. Внутри — всё, что
   сейчас разбросано по экрану: «Что тренировать» (чекбокс «Перевод»), группы измерений
   раздела, «Тип задания», «Количество заданий», сообщение о пустой выборке и главная
   кнопка «Начать» **в конце своего же тела**.

Заголовок этого блока подписывается действием, а не существительным: «Настроить тренировку
форм» — это и есть та «кнопка сконфигурировать», которую надо нажать первой.

Порядок блоков 2–3 в этой задаче фиксированный; задача 33 делает его динамическим по
частоте использования (и явно закрепляет «Тренировку форм» внизу, если она непопулярна).

---

## 2. Компонент `TrainingBlock`

Новый `features/training-setup/components/TrainingBlock.tsx` — единственный носитель
disclosure-поведения, повторно используемый всеми блоками (тот же принцип «единый
параметризуемый компонент», что уже действует для экрана в целом, FR-113):

```tsx
interface TrainingBlockProps {
  readonly id: string           // стабильный идентификатор блока (нужен задаче 33)
  readonly title: string
  readonly summary: string      // одна строка под заголовком, видна и в свёрнутом виде
  readonly open: boolean
  readonly onOpenChange: (open: boolean) => void
  readonly children: React.ReactNode
}
```

Реализация — нативная семантика раскрытия: заголовок это `<button type="button">` с
`aria-expanded` и `aria-controls`, тело — регион с этим `id`, свёрнутое тело **не в DOM**
(не `hidden`-скрытое), чтобы контролы свёрнутых блоков не попадали в таб-порядок и в
axe-скан. Тач-таргет заголовка ≥ 44px, стрелка-индикатор `aria-hidden`.

Состояние раскрытия живёт в `TrainingSetupScreen` (`openBlockId: string | null`), режим —
аккордеон: открытие блока закрывает предыдущий. Так на 320px в поле зрения всегда ровно
одна форма и её кнопка. Ничего не персистится: при следующем заходе экран снова свёрнут.

---

## 3. Что меняется в `TrainingSetupScreen.tsx`

- JSX разрезается на «Выборку слов» и блоки; порядок и содержимое — по §1. Логика
  `config`/`updateConfig`/`handleStart`/`handleStartMatching`/`handleStartExtra`,
  загрузка `lastPracticeConfig`, `applyIncomingFilter`, `usePracticeCandidateWords` и
  `buildPracticeQueue`-превью **не меняются** — это чисто перекладка разметки.
- Единственное поведенческое уточнение: `handleSectionChange` (смена таба раздела) больше
  не должна схлопывать открытый блок — смена раздела меняет выборку, а не то, что открыто.
- Счётчик «Найдено N слов, M форм» переезжает в «Выборку слов» (он описывает выборку, а не
  конфигуратор) и остаётся `role="status" aria-live="polite"`.
- Сообщение «Под эти фильтры не попало ни одного слова…» остаётся у кнопки, к которой
  относится, — внутри блока «Тренировка форм слов»; блоки-пресеты показывают своё
  собственное пояснение при пустой выборке (задача 31 §3).
- Кнопки «Начать» больше не подписаны одинаково вне контекста: у каждой — `aria-label` вида
  «Начать: выбор перевода», чтобы скринридер и e2e различали их без опоры на порядок в DOM.

---

## 4. E2E и тесты

- Существующие e2e-сценарии Practice начинаются с открытия нужного блока — добавляется
  один хелпер `openTrainingBlock(page, title)` в `e2e/support/`; селекторы кнопок «Начать»
  переводятся на `aria-label` из §3, а не на порядковый номер.
- `TrainingBlock` покрывается юнит-тестом: `aria-expanded` переключается, свёрнутое тело
  отсутствует в DOM, открытие второго блока закрывает первый.
- axe-скан экрана (задача 26) должен проходить в обоих состояниях — со всеми блоками
  свёрнутыми и с открытым конфигуратором.

# 45 — Точность: засчитывается только чистый первый ответ

**Зависит от:** 14, 15, 29, 42
**Результат:** «Точность» (на главном и в результатах сессии) считает верным только ответ, данный
чисто с первой попытки в сессии. Ошибка при наборе понижает точность, даже если слово потом
исправлено той же попыткой или верно отвечено при повторе в той же сессии.

---

## Требования: FR-86 (распространяет «не засчитывается как выученное» на статистику)

## Зачем

Запрос пользователя: «Если слово было введено неправильно, это должно понижать точность даже в
случае исправления в той же сессии».

Сейчас есть три источника «точности», и все три засчитывают исправленную ошибку как успех:

| Где | Как считается | Что не так |
|---|---|---|
| Главная, «Точность за сегодня» (`HomePage.tsx`) | `dailyStats.correctCount / reviewsCount` | Считаются **все** ответы, включая повторы внутри сессии (`SessionRunner` requeue). Ошибка + верный повтор = 50% вместо 0%. Набор с исправленной буквой — `gradeResult.correct = true`, то есть 100% |
| Итог сессии (`build-session-summary.ts`) | первые логи по навыку, `rating !== AGAIN` | Набор с ошибкой/подсказкой — рейтинг Hard, считается верным |
| Итог сессии по измерениям | первые логи, `log.correct` | То же: `correct = true` для набора с исправлением |

Корень проблемы: `reviewLog.correct` / `gradeResult.correct` означает «ответ в итоге совпал», а не
«ответил сам и сразу». Это правильно для SRS (рейтинг и так опущен до Hard), но не для точности.

---

## 1. Определение

Ответ **чистый**, если:

- выбор: `gradeResult.correct`;
- набор: `gradeResult.correct && isFlawlessAttempt(attempt)` — без ошибок, подсказок и «глазка»
  (одна функция с задачами 41 и 42);
- near-miss (таблицы): не чистый.

В точность идёт только **первый ответ на навык в сессии** (`isFirstAnswerInSession`, уже
передаётся в `submitAnswer`). Повторы после ошибки не входят ни в числитель, ни в знаменатель:
иначе исправление в той же сессии тянет точность вверх, чего пользователь как раз не хочет.

## 2. Данные

- `ReviewLogRecord` получает `clean?: boolean` и `firstInSession?: boolean`. Пишутся
  `answer-pipeline.ts#submitAnswer` для каждого нового лога. Старые логи без полей: `clean`
  считается как `correct && rating !== HARD`, `firstInSession` — как `srsApplied` (`policy.ts#shouldApplySrs`:
  совпадает с «первым ответом в сессии» везде, кроме режима `mistakes`, — для старых данных
  это допустимое приближение).
- `DailyStatsRecord` получает `accuracyAttempts?: number` и `accuracyClean?: number`;
  `answer.repository.ts#applyAnswer` увеличивает их только для `firstInSession`.
  `reviewsCount` / `correctCount` остаются как есть (счётчик повторений на главной ими
  пользуется).
- `SkillRecord.correct` / `incorrect` / `correctStreak` **не меняются**: они управляют прогрессией
  этапов (задача 40), и менять им смысл — отдельное решение. Проверить потребителей
  `correct`/`incorrect` (`aggregate.ts`, карточка слова): если где-то в UI это показывается как
  «точность», перевести на новое определение или переименовать подпись.

Миграция схемы Dexie не нужна: поля опциональные и не индексируются.

**Добавлено при реализации:** `ReviewLogRecord` получил ещё `assist?: 'hinted' | 'corrected'` — чем
не безупречен верный набор (правило — `letter-attempt.ts#assistOf`, то же, что даёт статус
`hinted`/`corrected` панели фидбэка). Без него итог сессии (§3) не отличил бы «с исправлением» от
«с подсказкой»: из одного `clean: false` этого не восстановить. Опциональное, как и остальные поля;
`backup.schema.ts` получил все три новых поля лога и оба счётчика дня (формат бэкапа не менялся,
версия не растёт).

## 3. Потребители

- `HomePage.tsx`: `accuracyClean / accuracyAttempts`, если `accuracyAttempts > 0`. Для дня, у
  которого есть только старые счётчики, — прежняя формула.
- `build-session-summary.ts`: `correctCount` и `accuracy` по измерениям считаются по `clean`
  (с фолбэком из §2). Список ошибок `mistakes` остаётся по `!log.correct`, а ответы с
  исправлением показываются там же с пометкой «с исправлением» / «с подсказкой». Иначе процент
  падает, а объяснения в списке нет.
- `SessionRunner.tsx#summarizeSession` (если он дублирует формулу): то же определение, одна
  функция `isCleanLog(log)` в `learning/`, без копий.

## 4. «Сопоставление»

Засчитанная пара (задача 44) — чистый первый ответ по обоим навыкам. Запятнанные слова логов не
пишут и в точность не входят. Это осознанное решение, следующее прямой формулировке «не
засчитываются» из задачи 44. Если пользователь захочет, чтобы ошибка в сопоставлении тоже
понижала точность, нужен отдельный лог «неверно» на запятнанные слова без SRS-эффекта.

---

## Границы

- SRS, рейтинги, серии и прогрессия этапов не меняются.
- Задним числом `dailyStats` не пересчитываются: старые дни показывают старую точность.
- Режим «Повторить ошибки» (`mode: 'mistakes'`) — отдельная сессия; её первый ответ на навык
  входит в точность как обычно.

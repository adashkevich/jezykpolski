# 50 — Карточка слова: значения с пояснением, примером и уровнем

**Зависит от:** 47, 49
**Результат:** на карточке слова каждое значение показывает переводы, польское пояснение
(`gloss_pl`), пример (`example_pl`) и свой уровень; primary-значение помечено как изучаемое, прочие —
«позже». После ответа в упражнении фидбэк показывает пример primary-значения.

---

## Зачем

`SensesList` сейчас печатает `sense.ru` и `sense.en`; `en` в v2 нет, зато появились пояснение и
пример — самое полезное из переработки словаря. А раз учим только primary (задача 49), пользователь
должен видеть, какое из значений сейчас в работе, иначе «прочие» значения на карточке выглядят как
то, что он уже должен знать.

## 1. `useSenses` / `SensesList`

- `useSenses` дополнительно запрашивает `getSenseDetails(wordId)` (задача 47 §4). Детали грузятся
  отдельно: переводы показываются сразу из уже прогретого шарда, пояснение и пример дорисовываются,
  когда придёт шард деталей. Ошибка загрузки деталей не ломает список — только скрывает
  пояснения (без сообщения об ошибке: офлайн без прогретого шарда — штатная ситуация).
- `key` элемента — `sense.id`, а не индекс.
- Разметка значения:
  ```
  1. закон, право                         [A2] [изучаем]
     ogół przepisów obowiązujących w państwie
     «Prawo zabrania palenia w restauracjach.»
  ```
  - переводы — переводы активного профиля (задача 51; до неё — `ru`);
  - пояснение — `text-body-sm text-muted-foreground`, `lang="pl"`;
  - пример — курсивом, `lang="pl"`;
  - бейдж уровня значения (уровень активного профиля); бейдж «изучаем» — у primary, у прочих
    приглушённый «позже». Если значение одно — бейджи «изучаем/позже» не показываются.
- Primary всегда первым (порядок шарда, задача 47 §3).

## 2. Пример в фидбэке упражнения

`ExerciseFeedback` для vocab-упражнений (`choice`/`input`/`self-assess`, оба направления) после
ответа показывает `example_pl` primary-значения строкой под правильным ответом. Источник —
`SessionContentContext`: детали шарда грузятся в том же `prepare(wordId)`, что и переводы, но
**не блокируют** показ вопроса — если шард деталей не успел, пример просто не выводится.
В matching и грамматических упражнениях пример не выводится.

Пример не должен подсказывать ответ **до** ответа: выводится только в состоянии фидбэка.

## 3. Список слов

`WordRow` — без изменений (`primaryRu`). Поиск по русскому — по-прежнему по `primaryRu`; поиск по
переводам прочих значений не добавляется (индекс не несёт их, а грузить шарды для поиска дорого).

## Реализация — где отступает от текста выше

- **Профиль для бейджа уровня.** `SensesList` принимает `profile: LangProfile` и берёт
  `sense.levels[profile]`; `WordDetailPage` передаёт `DEFAULT_LANG_PROFILE` из нового
  `learning/session/lang-profile.ts` (`'ru'`). Задача 51 дописывает в этот файл ключ настройки и
  подставляет в `WordDetailContent` активный профиль вместо константы; строка переводов `by`/`ua`
  встаёт под `sense.ru` в том же `SensesList`.
- **Детали и `useSenses`.** Второй эффект хука зовёт `getSenseDetails(wordId)` независимо от
  значений; `details` — пустая `Map`, пока шард не пришёл, и остаётся пустой при отказе (ошибка
  глотается без сообщения). Бейдж уровня виден и у единственного значения (как в спеке); не
  показываются только «изучаем»/«позже».
- **Пример в фидбэке.** `content/senses.ts#getPrimaryExample(wordId)` — пример primary-значения
  (по флагу, через `getSenses` + `getSenseDetails`). `SessionContentCache.preload` запускает его
  в фоне **после** загрузок, нужных вопросу (переводы и парадигма), и не ждёт; результат читает
  синхронный `getPrimaryExample(wordId)` — `undefined`, пока шард не пришёл или если он недоступен
  офлайн. Повторный `preload` слова новый запрос не делает (в том числе после отказа). Пример
  читается в момент показа фидбэка — пришедший позже не перерисовывается.
- **Какие упражнения.** `answer-pipeline.ts#showsWordExample` — `switch` без `default` по типам
  упражнений: `choice`/`input`/`self-assess` — да, остальное — нет (новый тип нельзя добавить, не
  решив это). `ActiveQuestion` читает пример только при `feedback !== null`.
- **Где строка.** `ExerciseFeedback` получил необязательный `example`; строка (курсив, `lang="pl"`,
  «…») идёт отдельным абзацем под блоком статуса, а не внутри цветной панели, — при верном ответе
  панели нет (ответ показывает само упражнение), и пример всё равно виден.
- **axe.** В репозитории нет `vitest-axe`/`jest-axe`: axe-скан — `@axe-core/playwright` в
  `e2e/accessibility.spec.ts`. Добавлен тест карточки `być` (два значения, пояснение, пример,
  «изучаем»/«позже») на реальном собранном контенте.
- **Реальные данные.** Порядок и примеры `być`/`to` проверены одноразовым скриптом по
  `public/content/{senses,sense-details}`: `być:copula` — primary, пример «Anna jest lekarką.»;
  `być:exist` — «Czy na Marsie jest życie?»; во всём корпусе primary идёт первым, а у каждого
  значения есть запись деталей. В юнит-тестах — фикстуры с теми же записями (`public/content`
  в git не лежит и тестами не читается), у `być` в фикстуре primary записан вторым.
- **Известный компромисс.** `preload` вызывается для всей очереди при старте сессии, так что в
  фоне качаются шарды деталей всех слов очереди (до 16 шардов по ~160 КБ без сжатия, дедуплицируются
  по номеру шарда). Вопрос это не блокирует, но делит канал с загрузкой остального. Ленивый
  вариант — запрашивать пример при показе вопроса — не делался: спека требует «в том же
  `prepare`».

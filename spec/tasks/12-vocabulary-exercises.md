# 12 — Vocabulary-упражнения

**Зависит от:** 09, 10
**Результат:** UI-компоненты всех vocabulary-типов упражнений.

---

## Требования: FR-50 … FR-57

## Шаги

### 1. Общий контракт

```ts
interface ExerciseProps<E extends Exercise> {
  exercise: E;
  onAnswer(answer: string): void;   // runner сам вызовет grade
  feedback: GradeResult | null;     // null = ещё не отвечено
  disabled: boolean;
}
```

Компонент упражнения **не проверяет ответ сам** и не пишет в БД — только собирает ввод.
Проверка — `grade` (задача 09), запись — runner (задача 13).

### 2. Типы MVP

| Компонент | Тип | Направление |
|---|---|---|
| `ChoiceExercise` | `choice` | pl-ru и ru-pl |
| `InputExercise` | `input` | pl-ru и ru-pl |
| `SelfAssessExercise` | `self-assess` | показать ответ → `Не знаю / Трудно / Знаю` |

`MatchingExercise` (FR-55) — следующая фаза, после стабилизации трёх основных.

### 3. `ChoiceExercise`

4 варианта, крупные тач-таргеты (≥ 44px, NFR-11).
После ответа: правильный вариант подсвечивается **и** помечается иконкой; выбранный неверный —
тоже цветом и иконкой (не полагаться на цвет, NFR-11).
Клавиатура: цифры 1–4 выбирают вариант, Enter — далее.

### 4. `InputExercise`

Поле ввода, автофокус, `autocapitalize="off"`, `autocorrect="off"`, `spellcheck={false}` —
иначе мобильная клавиатура будет исправлять польские слова.

Обработка `nearMiss` (задача 09): показать «Почти! Проверь диакритики» и подсветить
отличающиеся символы. Это не «неверно», но и не «верно».

Для польского ввода — подсказка с быстрым доступом к `ą ć ę ł ń ó ś ź ż`
(мобильная клавиатура может их не давать без переключения раскладки). Не обязательно для MVP,
но заметно влияет на удобство.

### 5. `SelfAssessExercise`

Две фазы: промпт → `Показать ответ` → ответ + три кнопки рейтинга.
Кнопки должны показывать предполагаемые интервалы (`previewIntervals` из задачи 11) —
это даёт пользователю обратную связь о работе алгоритма.

### 6. Обратная связь

Единый компонент `ExerciseFeedback`: верно / почти / неверно + правильный ответ + кнопка «Далее».
Поддержка `prefers-reduced-motion` (NFR-11): без анимации, если пользователь её отключил.

### 7. Клавиатура

Во всех типах: Enter — подтвердить/далее. Фокус переводится на поле ввода / первый вариант
автоматически при смене вопроса — иначе прохождение сессии с клавиатуры невозможно.

## Acceptance

- [ ] Все три типа рендерятся и корректно передают ответ наверх
- [ ] Компоненты не импортируют `db` и не вызывают `grade` сами
- [ ] Верный/неверный ответ различим без цвета (иконка или текст)
- [ ] `nearMiss` показывается отдельным состоянием, не как «неверно»
- [ ] Поле ввода не автокорректируется мобильной клавиатурой
- [ ] Прохождение сессии полностью с клавиатуры работает (Tab / цифры / Enter)
- [ ] `prefers-reduced-motion` отключает анимации
- [ ] Тач-таргеты ≥ 44px на 320px-вьюпорте
- [ ] Component-тесты (RTL): выбор варианта, ввод ответа, самооценка
